Research brief

In this module you will

  • set up a simulation study from geometry to outputs
  • run a scenario in an open-source simulator and repeat it with several seeds
  • carry out a sensitivity analysis and report percentiles
  • combine macroscopic and microscopic models across scales
Spoken overview
Read the transcript

A simulation of a mass gathering is a chain of choices, and each link can break. First the geometry: walkable areas, walls, gates, stairs and ramps, from site plans and checked on site. Then demand: how many people, arriving when, going where, often from schedules and counts. Then the model: macroscopic for the whole network, microscopic for hot spots, calibrated as in Go 2. Then the runs: stochastic models give different answers with different random seeds, so run each scenario several times. Then sensitivity: vary the uncertain inputs, such as pre-movement times, walking speeds and compliance with schedules, and see how much the outputs change. Finally the outputs that answer your question, such as risk exposure or time to clear, reported with their spread. Open-source simulators make this transparent and reproducible. In this module you run a gate scenario in JuPedSim, a simulator from Forschungszentrum Jülich, repeat it with several seeds and gate widths, and add a simple sensitivity analysis. JuPedSim reproduces bottleneck flows of about one point one people per metre per second here, consistent with experiments.

Geometry and demand

Build the geometry from site plans, then check it on site: temporary stalls, barriers and vehicles change effective widths. Demand comes from schedules, ticketing and counts: how many, when, from where to where, and with what profile (speeds, groups, mobility). For the Hajj, group schedules and routes are key inputs.

Running a scenario in JuPedSim

JuPedSim is an open-source simulator with a Python interface (pip install jupedsim). The lab builds a 20 m × 10 m forecourt emptying through a gate, places 150 people with the collision-free speed model, and repeats each gate width with 5 seeds. Results: 1.0 m gate about 143 s, 1.6 m about 80 s, 2.4 m about 57 s, with flows of about 1.05 to 1.18 people per metre per second, consistent with experiments.

Run it yourself

Download the JuPedSim script, install JuPedSim, and add a 3.2 m gate. Is the flow per metre still about the same?

Seeds and sensitivity

Stochastic models differ between runs: report the mean and spread over seeds. Then vary uncertain inputs. In the explorer, ± 50% uncertainty in pre-movement and ± 20% in specific flow spread the egress time widely; the 95th percentile, not the median, is what safety depends on. Screen inputs one at a time first, then study the important ones jointly.

One run is an anecdote

A single stochastic run can be unusually good or bad. Never report one run as the result.

Across scales

No single model fits a whole mass gathering. A common approach couples a fast network or macroscopic model for the whole site and timetable with microscopic models for critical spots such as ramps, junctions and gates. The coupling passes flows and densities at the boundaries. Check that both models agree where they overlap.

Implement it

Code from the Go 3 research kit. Python marked 'Runs in your browser' runs here; the longer scripts are for your own machine.

A gate scenario in JuPedSimPythonDownload
"""Lab 3.6: a gate scenario in JuPedSim (open source, https://www.jupedsim.org). pip install jupedsim
A 20 m x 10 m forecourt empties through a gate. Compare gate widths and repeat with several seeds:
report the mean and spread of the evacuation time, not one run."""
import statistics
import jupedsim as jps
from shapely import Polygon

def run(gate=1.2, n=150, seed=1, v0=1.2):
    y0, y1 = 5 - gate / 2, 5 + gate / 2
    area = Polygon([(0, 0), (20, 0), (20, y0), (22, y0), (22, y1), (20, y1), (20, 10), (0, 10)])
    sim = jps.Simulation(model=jps.CollisionFreeSpeedModel(), geometry=area)
    exit_id = sim.add_exit_stage([(21.5, y0), (22, y0), (22, y1), (21.5, y1)])
    jid = sim.add_journey(jps.JourneyDescription([exit_id]))
    start = Polygon([(0.5, 0.5), (15, 0.5), (15, 9.5), (0.5, 9.5)])
    for p in jps.distribute_by_number(polygon=start, number_of_agents=n, distance_to_agents=0.5, distance_to_polygon=0.3, seed=seed):
        sim.add_agent(jps.CollisionFreeSpeedModelAgentParameters(journey_id=jid, stage_id=exit_id, position=p, desired_speed=v0))
    while sim.agent_count() > 0 and sim.elapsed_time() < 600:
        sim.iterate()
    return sim.elapsed_time()

if __name__ == "__main__":
    for gate in [1.0, 1.6, 2.4]:
        times = [run(gate=gate, seed=s) for s in range(5)]
        print(f"gate {gate} m: evacuation {statistics.mean(times):.1f} s (min {min(times):.1f}, max {max(times):.1f}), "
              f"flow {150 / statistics.mean(times) / gate:.2f} per m per s")
Requires pip install jupedsim (version 1.x). Builds the geometry with shapely, runs the collision-free speed model, repeats each gate width with 5 seeds.

Research notes

  • A simulation study chains geometry, demand, model, runs, sensitivity and outputs.
  • Check geometry on site; derive demand from schedules and counts.
  • Repeat stochastic runs and vary uncertain inputs; report percentiles.
  • Couple macro models for the site with micro models for hot spots; share code and data.

New words

Random seed
A number that fixes the random sequence of a stochastic simulation run.
Sensitivity analysis
Studying how outputs change with uncertain inputs.

Open-source pedestrian simulator from Forschungszentrum Jülich, with a Python interface.
Multi-scale coupling
Linking models of different detail at their boundaries.

The ability of others to rerun a study and get the same results.
